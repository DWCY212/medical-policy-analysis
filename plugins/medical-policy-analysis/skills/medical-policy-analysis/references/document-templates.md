# 五步输出模板

第一、三、四、五步输出 Markdown；第二步输出 Excel。所有 Markdown 在开头记录生成时间、任务标识、依据版本、联网核验日期和人工确认内容。

## 每一步的内容与共同规则

1. 第一步分析用户文件并联网核验官方标题、发布机关、管辖地区、发布日期、文号和官方来源网址，输出 `01-政策理解.md`。找不到官方信息时标记 `待确认文件`。
2. 第二步联网收集与主政策具有直接制度关系或同一问题链的政策，输出 `02-相关政策.xlsx`。工作簿必须包含政策总表、检索记录、待确认与排除、字段说明四个工作表。
3. 第三步基于第一、二步梳理政策时间线、演进阶段、阶段转换事件、关键转折和未闭合问题，输出 `03-政策演进.md`。
4. 第四步站在产品市场经理角度，使用前三步及必要的补充资料分析政策出台原因、问题、目标、解决路径和产品方向，输出 `04-初步分析.md`。内部方法不进入交付正文。
5. 第五步审核第四步的证据链和产品判断，重新联网复核关键官方来源、发布日期、文号和来源状态，输出 `{政策简称}政策分析.md`。

所有步骤都可以联网，第一、二、五步必须联网。所有政策事实和关键判断必须可追溯，不得虚构 URL、日期、文号、条款或官方意图。`发布日期` 统一指官网页面、官方公报或官方索引页显示的日期；与正文落款日期不一致时在备注中说明。

第一章整合前四步全部内容，直接回答“为什么出台、出现什么问题、要解决什么问题、怎么解决”，不能只写摘要句。第三章承接第三步的演进分析。第四章按四种证据类型分开写，每个关键判断紧跟来源编号或 URL。

将 `{X}` 替换为证据支持的实际层次数字，标题和正文层次数量必须一致，不在交付文档中保留占位符。建设优先级至少说明政策确定性、用户问题紧迫性、能力复用性、数据依赖、实施成本与合规风险。验证计划必须写明需要验证的假设、方法、数据、责任角色和判定标准；合规边界必须说明数据、医疗、宣传、支付和监管限制。第八章综合全部研究内容形成结论和产品设计方向判断，同时写明成立条件、主要风险和不宜外推的边界。
