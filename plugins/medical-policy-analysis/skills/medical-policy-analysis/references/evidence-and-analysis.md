# 产品市场视角的政策成因分析内部方法

## 内部分析逻辑

以下内容只指导内部推理，不在交付文案中复述框架名称、原始问题、政策潜规则措辞或后发型/先发型标签。把推理结果转化为有证据支撑的结论后，填入用户指定目录。

从产品市场经理角度，始终围绕以下两个判断开展分析：

1. 为什么要出台这个政策，出现了什么问题，要解决什么问题，怎么去解决；沿着这条主线思考业务和产品设计。
2. 国家政策大部分是在问题出现并经过时间、事件发酵后，用后续政策处理；少部分先发政策通常与大战略方向有关。分析非国家层级或其它管辖地区政策时，使用对应政策制定者和战略层级。

将以上判断展开为因果链：

```text
问题信号出现 -> 时间与事件发酵 -> 进入政策议程 -> 政策目标 -> 治理工具 -> 执行机制 -> 产品能力与市场机会
```

对每项关键政策回答：

1. 为什么政策制定者要出台该政策？
2. 出现了什么可观察问题，涉及哪些患者、支付方、机构、供应方或监管方？
3. 问题如何随时间、事件、投诉、成本、风险或战略变化而发酵，何时进入政策议程？
4. 政策要解决什么问题，分成几个层次？
5. 政策使用什么准入、支付、处方、供应、服务、数据、监管或考核机制解决？
6. 对产品定位、目标用户、核心场景、能力边界、建设优先级、验证计划和合规边界有什么启示？

当主政策属于国家层级时，可以回答“国家为什么出台”；其它层级或其它管辖地区改用相应的政策制定者，不强行套用中国国家叙事。

## 后发型与先发型政策

先判断政策属于哪种主要逻辑，也允许混合型：

- `后发型治理响应`：问题已经出现并经事件、统计、执行摩擦或舆情发酵，后续政策用于堵漏洞、统一规则、扩大覆盖或强化执行。
- `先发型战略布局`：问题尚未全面显性化，但政策与国家或地区大战略、人口结构、技术变革、产业安全、长期支付能力或制度前置建设有关。
- `混合型`：既处理已经显现的问题，也为长期战略建立基础能力。

判断后发型时寻找政策出台前的问题证据；判断先发型时寻找上位战略、规划、预算、人口或技术趋势。不能仅凭发布时间推断类型。

## 证据标签

| 标签 | 使用条件 | 写法要求 |
| --- | --- | --- |
| `[官方明确表述]` | 政策原文、官方解读、答问直接表达 | 引用文件、条款或段落和官方 URL |
| `[多来源支持的判断]` | 至少两个相互独立的官方或可靠资料支持 | 列出来源，不把相关性写成确定因果 |
| `[基于政策演进的推断]` | 从时间、事件、层级、对象或工具变化推导 | 写出推理链和支撑政策 |
| `[待验证假设]` | 超出已有证据的产品或市场假设 | 写明需要的统计、访谈、试点或文件 |

新闻、统计数据、论文和行业资料可以补充问题背景，不替代政策原文。不得把产品判断包装成政府官方意图。

## 产品市场经理输出要求

### 核心结论

第一章必须整合所有政策事实、演进阶段、问题证据、解决目标和治理工具，依次回答：

1. 为什么要出台这个政策；
2. 出现了什么问题；
3. 要解决什么问题；
4. 怎么去解决。

不得只复述政策条款，也不得将没有证据的因果关系写成定论。

### 产品定位

至少回答：目标用户、核心问题、使用场景、购买或决策者、支付或预算来源、产品承诺、非目标范围、政策依赖和合规边界。

### 建设优先级

用 `P0/P1/P2` 或高/中/低分级，并解释：

- 政策确定性与执行强制性；
- 用户问题紧迫性和覆盖规模；
- 能力复用性和对后续政策的适配性；
- 数据、接口、组织协同和外部依赖；
- 实施成本、合规风险和证据缺口。

不得只给功能清单。每项优先级必须回到政策条款、问题链或可验证业务假设。

### 验证计划与合规边界

对每项关键产品判断说明：

- 待验证假设和当前证据缺口；
- 验证方法、所需数据、访谈对象或试点场景；
- 负责或参与验证的业务角色；
- 通过、调整或停止的判定标准；
- 涉及的数据权限、个人信息、医疗安全、支付规则、宣传表述和监管边界。

不得把政策允许或鼓励的方向直接等同于具体产品已获准上线，也不得用政策研究替代医疗、法律或合规审查。

### 结论与方向判断

第八章必须综合全文回答产品是否值得进入、优先服务谁、先建设什么能力、哪些方向暂缓，并说明结论成立的政策条件、业务条件、主要风险和不宜外推的边界。不要把第八章写成第一章的简单重复。

## 审核清单

- 第一章完整回答为什么出台、出现什么问题、要解决什么问题、怎么解决。
- 政策原文事实与问题推理分开。
- 后发型或先发型判断有时间与证据支撑。
- 每个关键判断可追溯到来源编号或 URL。
- 没有把“相关”写成“导致”，没有把地方试点直接外推为普遍结论。
- 第四章分别呈现官方明确表述、多来源支持的判断、基于政策演进的推断和待验证假设。
- 产品定位、建设优先级、验证计划和合规边界包含目标用户、场景、依赖、风险和验证动作。
- 第八章给出结论和产品设计方向判断，并写明成立条件和边界。
- 待确认文件、转载、失效网址和替代解释没有被静默删除。
- “政策潜规则”及后发型、先发型等内部分类没有出现在交付目录和正文。
