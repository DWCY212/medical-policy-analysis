# 第二步 Excel 输出规范

## 文件与工具

输出 `02-相关政策.xlsx`。使用 `$spreadsheets:Spreadsheets` 及其规定的电子表格工具创建、检查、渲染和导出工作簿。不要用 CSV、HTML 表格或改扩展名文件代替 XLSX。

若用户未提供模板，使用安静、专业、适合政策研究的表格样式。来源 URL 在单元格中保留完整纯文本。

## 工作表

### 1. 政策总表

每行一份纳入政策，列顺序如下：

| 列 | 字段 | 规则 |
| --- | --- | --- |
| A | 序号 | 连续整数 |
| B | 政策标题 | 官方标题 |
| C | 管辖地区 | 国家或地区及必要的省州、市 |
| D | 发布机关 | 正式机关名称 |
| E | 行政/监管层级 | 国家/中央、省州/区域、市/地方或等效层级 |
| F | 发布日期 | 官方网页、公报或索引页显示的日期；使用真正日期值，显示格式 `yyyy-mm-dd` |
| G | 文号/文件编号 | 文本，保留原格式 |
| H | 官方来源网址 | 完整纯文本 URL，找不到写 `待确认文件` |
| I | 来源类型 | 原文、转载、待确认文件、需人工审核 |
| J | 政策对象/主题 | 简洁关键词 |
| K | 政策工具 | 支付、准入、处方、供应、服务、数据、监管、考核等 |
| L | 关联强度 | 强-直接制度关系、强-同一问题链、中-背景补充 |
| M | 与主政策关联理由 | 写清上下位、对象、问题、工具或演进关系 |
| N | 演进角色 | 前身、上位依据、配套、试点、实施、调整、替代、背景等 |
| O | 核验日期 | 本次联网核验日期 |
| P | 备注 | 正文落款与官网日期差异、转载机关、失效状态等 |

正文落款日期通常与发布日期相同，不单列。少数不一致时，F 列使用官网显示的发布日期，并在 P 列记录正文落款日期和差异。

核心筛选默认只显示两类“强”相关政策；中等相关只在确有背景价值时保留并明确标识。

### 2. 检索记录

列出：序号、管辖地区、目标机关、检索关键词/检索式、检索日期、命中页面、页面 URL、处理结果、备注。

### 3. 待确认与排除

列出：材料标题、类型（待确认/需人工审核/中等背景/弱相关排除）、已知信息、缺失信息、来源线索、排除或待确认理由、建议人工动作。

### 4. 字段说明

解释每个字段、发布日期定义、来源类型和关联强度。明确“发布日期”不等于搜索日期、抓取日期、下载日期或 PDF 元数据日期。

## 格式要求

- 为每个工作表设置清晰标题和一致表头；冻结首行并启用筛选。
- 对长标题、关联理由和备注启用自动换行，控制列宽和行高，避免截断。
- 日期使用真正的 Excel 日期值和 `yyyy-mm-dd` 格式；文号保持文本。
- 不创建空白默认工作表，不合并数据区单元格，不使用难以辨认的颜色。
- 对待确认、转载、需人工审核使用克制且可区分的状态样式，不只依赖颜色传达含义。

## 交付前验证

1. 检查四个工作表及必填列存在。
2. 抽查政策标题、发布日期、文号和 URL 与官方页面一致。
3. 扫描 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A` 等错误。
4. 渲染并目视检查所有工作表，修复标题、日期、URL、长文本截断或重叠。
5. 导出后重新确认文件是可打开的 `.xlsx`，再更新状态为 `generated`。
